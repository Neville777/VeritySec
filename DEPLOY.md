# VeritySec Deployment Guide

## Architecture

```
┌─────────────┐     HTTPS     ┌───────────────┐     TCP/SSL     ┌──────────┐
│   Vercel     │ ───────────→ │    Render      │ ─────────────→ │  Neon    │
│  (Frontend)  │   API calls   │   (Go API)     │   PostgreSQL   │   (DB)   │
│  Static SPA  │               │   Port 8765    │                │          │
└─────────────┘               └───────────────┘                └──────────┘
```

## 1. Neon Database

1. Create a Neon project at https://neon.tech
2. Copy the connection string: `postgresql://user:pass@host/dbname`
3. The Go backend auto-creates all tables on first connect

## 2. Render Backend

1. Create a **Web Service** from your repo
2. Set **Root Directory**: `.` (repo root)
3. Set **Dockerfile Path**: `./Dockerfile`
4. Add environment variables:
   - `DATABASE_URL` = your Neon connection string
   - `CORS_ORIGINS` = `https://veritysec.vercel.app` (your Vercel URL)
   - `PORT` = `8765`
   - `GIN_MODE` = `release`
   - `TLS_ENABLED` = `false` (Render handles TLS)
5. Health check path: `/api/health`

## 3. Vercel Frontend

1. Create a new project, set **Root Directory**: `frontend`
2. Framework preset: **Other**
3. Build command: `node build.js`
4. Output directory: `dist`
5. Add environment variable:
   - `API_URL` = `https://veritysec-api.onrender.com` (your Render URL)

## Local Development

No changes needed — the app still works as a monolith:

```bash
./veritysec   # serves both frontend + API on https://127.0.0.1:8765
```

When `DATABASE_URL` is set, it uses PostgreSQL. Otherwise, SQLite (default).
When `API_URL` is empty (local mode), the frontend calls same-origin.

## Environment Variables

| Variable | Where | Purpose |
|----------|-------|---------|
| `DATABASE_URL` | Render | Neon PostgreSQL connection string |
| `VERITYSEC_SECRET_KEY` | Render | Encryption key for BYOK API keys (auto-generated by Render) |
| `CORS_ORIGINS` | Render | Comma-separated allowed frontend origins |
| `PORT` | Render | Server port (default: 8765) |
| `GIN_MODE` | Render | `release` for production |
| `TLS_ENABLED` | Render | `false` — Render terminates TLS |
| `API_URL` | Vercel | Full backend URL for cross-origin API calls |
| `APP_VERSION` | Vercel | Version string shown in UI |

## Nmap / Security Notes

- Render provides DDoS protection and TLS termination
- Admin endpoints require JWT authentication
- Rate limiting is handled by Render's infrastructure
- CORS restricts API access to your Vercel domain only
- The `/api/health` endpoint is the only unauthenticated route
